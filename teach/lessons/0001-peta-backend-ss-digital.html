🗺️ Peta Besar: 4 Lapisan Backend

Bayangkan backend seperti restoran — ada dapur, ada kasir, ada pramusaji, ada manajer. Masing-masing punya peran berbeda. Di SS Digital, arsitekturnya begini:

┌─────────────────────────────────────────────────────────────────┐ │ LAPISAN 1: CLIENT (Frontend Apps) │ │ apps/portal, apps/pos-kasir, apps/absensi, apps/stok … │ │ → Next.js di cPanel server, diakses browser/HP karyawan │ └─────────────────────┬───────────────────────────────────────────┘ │ HTTPS Request ▼ ┌─────────────────────────────────────────────────────────────────┐ │ LAPISAN 2: EDGE FUNCTIONS (Serverless) │ │ supabase/functions/ → Deno runtime, jalan di CDN Supabase │ │ Contoh: submit-attendance, admin-create-staff, send-push … │ │ → Logic yang tidak boleh jalan di browser (rahasia, aman) │ └─────────────────────┬───────────────────────────────────────────┘ │ SQL / RPC Calls ▼ ┌─────────────────────────────────────────────────────────────────┐ │ LAPISAN 3: DATABASE (PostgreSQL via Supabase) │ │ Tables, Views, RPC (stored procedures), Triggers, pg_cron │ │ RLS (Row Level Security) — penjaga akses data │ │ Realtime — WebSocket untuk update live │ └─────────────────────┬───────────────────────────────────────────┘ │ Read/Write ▼ ┌─────────────────────────────────────────────────────────────────┐ │ LAPISAN 4: STORAGE + EXTERNAL │ │ Supabase Storage (foto selfie, struk, gambar menu) │ │ Ecosystem DB (Supabase project terpisah — sumber Order Online) │ │ cPanel cron + Passenger (untuk hosting Next.js) │ └─────────────────────────────────────────────────────────────────┘
🍔 Analogi Restoran

Client = pramusaji yang memanggil pesanan ke dapur.
Edge Function = kepala dapur yang memvalidasi pesanan sebelum masuk ke sistem.
Database = dapur utama — semua masakan (data) disiapkan di sini.
Storage = gudang bahan baku (gambar, file).

⚡ Komponen Mana yang Paling Rawan?

Bukan semua bagian sama bahayanya. Berdasarkan struktur project ini, ini ranking risiko performa:

🔴
Database Queries (PALING SERING jadi masalah)
Query lambat = semua app lambat. Apalagi views seperti monitoring_view_spv yang join banyak tabel sekaligus.
🟡
Row Level Security (RLS) Policies
RLS yang buruk bisa bikin setiap query ikut menjalankan subquery tambahan. 19 outlet × banyak tabel = potensi lambat.
🔵
Triggers & pg_cron Jobs
Trigger BOM otomatis, sync POS sales, push notification — kalau ada yang gagal, data bisa tidak konsisten.
🟢
Edge Functions
Relatif stabil — dipanggil saat dibutuhkan, tidak terus-menerus. Risiko utama: cold start dan timeout.
