Connection Pooling: Menghemat Batas Koneksi

Next.js server di cPanel sering membuat database kehabisan batas koneksi (Too many connections). Mari kita pelajari cara menyembuhkannya menggunakan Pooler.

🎯 Tujuan Lesson Ini

  • Memahami masalah **Connection Churn** pada server Node.js / Serverless
  • Memahami perbedaan koneksi langsung (port **5432**) dengan pooled connection (port **6543**)
  • Mengetahui perbedaan mode **Session** dan **Transaction** pada Supavisor
  • Bisa mengonfigurasi database URL yang aman dan efisien di file .env.local

1. Mengapa Database Kehabisan Koneksi?

Setiap kali Next.js memproses request server-side, aplikasi harus membuat koneksi ke PostgreSQL. Pembuatan koneksi ini membutuhkan jabat tangan (handshake) SSL/TLS yang lambat dan memakan RAM database.

Jika server Next.js di cPanel melayani banyak request secara bersamaan, ia akan membuka banyak koneksi ke database. Di Supabase Free Plan, batas maksimal koneksi langsung adalah **60 koneksi**. Jika melebihi batas ini, database akan crash dan mengembalikan error:

FATAL: remaining connection slots are reserved for non-replication superuser jobs
Tanpa Pooler: [Next.js Server] ─── (Buka 50+ Koneksi Langsung) ───▶ [PostgreSQL (Limit 60)] 💥 CRASH Dengan Pooler: [Next.js Server] ─── (Buka 50+ Koneksi) ───▶ [ Supavisor Pooler ] ─── (Reuse 5 Koneksi) ───▶ [PostgreSQL]

2. Apa itu Connection Pooling (Supavisor)?

Supabase menyediakan **Supavisor** — sebuah proxy khusus di depan database yang bertugas mengelola koneksi. Alih-alih membiarkan Next.js terhubung langsung ke Postgres, Next.js diarahkan ke Supavisor. Supavisor akan menahan koneksi-koneksi tersebut dan membagikannya secara bergantian (reuse) ke database utama.

Kamu hanya perlu mengganti **Port** pada database connection string di file .env.local:

  • Direct Connection (Langsung): Port **5432** (Gunakan hanya untuk migration script).
  • Pooled Connection (Pooler): Port **6543** (Gunakan untuk aplikasi Next.js/cPanel).

3. Mode Pooler: Session vs Transaction

Supavisor (port 6543) menyediakan dua mode utama yang disetel lewat string koneksi:

🔌 1. Session Mode

Satu koneksi diberikan penuh ke client dari awal login sampai logout/diskonet. Mirip dengan koneksi langsung. Kurang efisien untuk ribuan user, namun mendukung fitur Postgres penuh.

⚡ 2. Transaction Mode (Paling Direkomendasikan)

Koneksi ke database hanya diberikan saat client sedang mengeksekusi satu transaksi SQL (misal query SELECT), lalu **langsung dicabut** begitu query selesai untuk diberikan ke client lain. Sangat efisien! 5 koneksi fisik PostgreSQL bisa melayani 500+ client sekaligus.

Batasan: Mode ini tidak mendukung fitur session-level seperti PREPARE statements atau temporary tables.

🛠️ Konfigurasi Terbaik di Project SS Digital

Buka file .env.local kamu, pastikan konfigurasinya mengikuti format ini:

# URL untuk aplikasi Next.js (Menggunakan Pooler port 6543 + mode=transaction)
DATABASE_URL="postgres://postgres.ref:password@aws-0-ap-southeast-1.pooler.supabase.com:6543/postgres?pgbouncer=true&connection_limit=10"

# URL khusus untuk migrasi (Direct Connection port 5432)
DIRECT_URL="postgres://postgres.ref:password@db.ref.supabase.co:5432/postgres"
🧪 Cek Pemahaman

1. Kapan kamu wajib menggunakan port **6543** (Connection Pooler) alih-alih port standar **5432**?

2. Mengapa Transaction Mode sangat efisien dalam menghemat batas koneksi database?
