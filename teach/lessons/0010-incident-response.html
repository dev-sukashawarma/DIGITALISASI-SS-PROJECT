Incident Response: Penanganan Sistem Down

Ini adalah materi terakhir. Ketika aplikasi kasir POS down di tengah jam makan siang yang ramai, ini adalah panduan penyelamat hidupmu. Tetap tenang.

🎯 Tujuan Lesson Ini

  • Memiliki **Mental Model** yang benar saat menangani insiden sistem mati (down)
  • Mengetahui langkah isolasi masalah (Next.js server cPanel vs Supabase DB)
  • Tahu di mana letak tombol darurat **Database Restore (Point-in-Time Recovery)**
  • Memahami pentingnya audit pasca-insiden (Post-Mortem)

1. Protokol 4 Langkah Penyelamatan

Ketika sistem mengalami error massal atau mati total, jangan panik dan jangan langsung mengubah kode secara tergesa-gesa. Ikuti protokol ini:

Step 1: Bernapas & Batasi Kerusakan (Isolate)

Jangan langsung push perbaikan kode baru ke production jika kamu belum tahu akar masalahnya. Matikan fitur yang rusak (jika memungkinkan) atau pasang halaman maintenance di cPanel agar user tidak terus-menerus memicu error di database.

Step 2: Analisis Akar Masalah (Tanyakan 3 Hal)

  • Apakah Supabase Down? Cek status.supabase.com. Jika ya, ini masalah global, kita hanya perlu menunggu.
  • Apakah server cPanel yang down? Cek apakah website Next.js masih bisa diakses. Jika cPanel kehabisan resource/RAM, lakukan restart Node.js app via CloudLinux Selector.
  • Apakah database terkunci (Locked)? Buka Supabase Query Performance. Cek apakah ada query berat yang memblokir query lain.

Step 3: Mitigasi Tercepat (Bukan Solusi Sempurna)

Fokus pertama adalah membuat kasir/outlet bisa bertransaksi kembali, **bukan** membetulkan bug secara sempurna. Jika migrasi terakhir merusak skema database, lakukan Rollback atau kembalikan (Restore) database ke status 1 jam yang lalu.

Step 4: Laporan & Pencegahan (Post-Mortem)

Setelah badai reda, catat apa penyebabnya, mengapa bisa terobos ke production, dan apa yang harus diubah di sistem testing agar masalah yang sama tidak pernah terjadi lagi.

2. Tombol Darurat: Point-in-Time Recovery (PITR)

Jika terjadi musibah besar (misalnya database tidak sengaja terhapus, data keuangan rusak parah akibat bug, dsb.), Supabase menyediakan fitur **Database Restore (PITR)**.

Fitur ini memungkinkan kamu memutar balik waktu database ke **detik tertentu** di masa lalu secara presisi.

📍 Cara Melakukan Restore Database
  1. Buka Supabase Dashboard → Database → Backups.
  2. Pilih tab Point-in-Time Recovery (PITR).
  3. Masukkan tanggal dan jam tepat sebelum insiden terjadi (misalnya jam 11.58 siang).
  4. Klik Restore Database. Supabase akan membuat database kloningan baru berisi data persis di detik tersebut.
⚠️ Peringatan Restore

Proses restore akan menghapus data yang masuk *setelah* waktu restore yang kamu pilih. Pastikan kamu sudah mem-backup data transaksi terbaru ke file CSV/SQL lokal sebelum menekan tombol restore!
