Supabase Storage & Bucket Security

Aplikasi kita menyimpan banyak file gambar: foto selfie absen, foto verif kiriman bahan baku, dan gambar menu. Pelajari cara mengamankan bucket storage kamu di sini.

🎯 Tujuan Lesson Ini

  • Memahami perbedaan antara bucket **Public** dan **Private**
  • Bisa menulis policy RLS khusus untuk objek di Supabase Storage
  • Memahami konsep **Signed URL** untuk file privat sensitif
  • Menyadari pentingnya optimasi ukuran gambar sebelum di-upload

1. Jenis Bucket: Public vs Private

Supabase Storage membagi penyimpanan ke dalam wadah bernama **Bucket**. Wadah ini bisa disetel menjadi:

🌐 1. Public Bucket (Misal: menu_images)

File di dalam bucket ini bisa diakses langsung oleh siapa saja di internet lewat URL publik permanen. Cocok untuk aset publik yang tidak rahasia seperti gambar menu shawarma di kasir/kiosk.

🔒 2. Private Bucket (Misal: selfies, po_invoices)

File di dalam bucket ini tidak memiliki URL publik. Database menolak akses langsung kecuali user lolos dari aturan **Storage RLS Policies** atau memiliki **Signed URL** (token akses sementara berdurasi beberapa menit). Wajib digunakan untuk foto selfie absen karyawan dan struk nota belanja.

2. RLS Khusus Storage: Mengamankan Upload

Sama seperti tabel biasa, bucket storage di Supabase dilindungi oleh RLS pada tabel internal storage.objects. Mari kita lihat contoh pembuatannya dari file migrasi 20260711100300_finance_rls_storage.sql:

-- Hanya staff dengan role 'admin' atau 'admin_finance' yang boleh membaca invoice PO
CREATE POLICY "Finance can read invoices" ON storage.objects
  FOR SELECT TO authenticated
  USING (
    bucket_id = 'po_invoices' AND
    (public.is_admin() OR EXISTS (
      SELECT 1 FROM public.outlet_staff
      WHERE id = auth.uid() AND role = 'admin_finance'
    ))
  );

-- Mengizinkan upload ke bucket po_invoices
CREATE POLICY "Staff can upload invoices" ON storage.objects
  FOR INSERT TO authenticated
  WITH CHECK (
    bucket_id = 'po_invoices'
  );
🚨 Bahaya RLS Storage Terbuka

Jika kamu lupa menulis policy FOR SELECT pada bucket private, file akan tersimpan aman namun tidak akan pernah bisa dirender di halaman Next.js (browser mendapat error 403 Forbidden). Sebaliknya, jika policy INSERT tidak disaring berdasarkan bucket_id, user nakal bisa meng-upload file apa saja ke bucket mana saja!

3. Signed URL: Kunci Sementara

Untuk merender gambar dari bucket **Private** (seperti foto selfie absensi crew) secara aman di dashboard Next.js, backend Next.js memanggil Supabase API untuk membuat **Signed URL**:

// Next.js API server-side:
const { data, error } = await supabase.storage
  .from('selfies')
  .createSignedUrl('selfie_kru_bogor.jpg', 60) // Berlaku hanya 60 detik!

// Hasilnya: https://.../selfies/selfie_kru_bogor.jpg?token=abcdef123456...

Signed URL memiliki token kadaluwarsa. Setelah 60 detik, link tersebut mati dan tidak bisa diakses lagi oleh siapa pun di internet.

⚠️ Optimasi Gambar: Hemat Kuota Storage

Kamera handphone crew saat ini menghasilkan foto selfie dengan resolusi tinggi (4-8 MB per foto). Jika crew absen 2x sehari × 19 outlet × puluhan crew, kuota storage Supabase Free Plan (1 GB) akan **penuh dalam hitungan minggu**.

Solusi di Frontend: Selalu kompres dan perkecil ukuran gambar di sisi client (browser handphone crew) sebelum di-upload. Batasi lebar maksimal gambar menjadi 800px dan ubah kualitasnya menjadi 70-80% JPEG. Ini akan mereduksi ukuran file dari 5 MB menjadi **hanya 80 KB saja** tanpa kehilangan kejelasan visual!
